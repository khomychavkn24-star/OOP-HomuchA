# Самостійна робота №2

**Тема:** Перевантаження конструкторів: приклади та сценарії.  
**Проєкт:** `IndependentWork2`

## Опис виконаної роботи

У рамках самостійної роботи реалізовано клас `Product` для системи інтернет-магазину:

* **Поля та властивості:** Оголошено 5 приватних полів (`_id`, `_name`, `_price`, `_category`, `_stockCount`) та відповідні read-only властивості.
* **Перевантажені конструктори:**
  1. **Основний конструктор:** Приймає всі 5 параметрів для повної ініціалізації.
  2. **Скорочений конструктор:** Приймає лише `id`, `name`, `price` та викликає основний конструктор через `: this(id, name, price, "Uncategorized", 0)`.
  3. **Конструктор копіювання:** Приймає об'єкт-джерело `Product other` та делегує ініціалізацію основному конструктору за допомогою `: this(other.Id, other.Name, ...)`.
* **Перевизначення `ToString()`:** Реалізовано форматований вивід стану товару з підтримкою валютного формату `:C`.

У файлі `Program.cs` продемонстровано створення товарів за допомогою кожного з трьох конструкторів.

## Контрольні запитання

1. **Навіщо потрібне перевантаження конструкторів у класі Product?**  
   Забезпечує гнучкість створення об'єктів з різним рівнем деталізації даних.
2. **Чому конструктор копіювання зручно реалізовувати через `: this(...)`?**  
   Запобігає дублюванню коду ініціалізації (принцип DRY).
3. **Які переваги дає read-only доступ до властивостей після створення об’єкта?**  
   Захищає стан об'єкта від несанкціонованих змін (забезпечує immutability).
4. **У яких випадках перевизначення `ToString()` спрощує налагодження?**  
   Дозволяє зручно виводити повний стан об'єкта в консоль або логи одним викликом.
